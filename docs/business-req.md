## 1. 文件目的與範圍

### 1.1 目的

本文件為**壽險新保件保費試算系統 MVP** 的業務需求權威來源，供業務單位、精算部門、開發團隊及測試人員共同確認驗收標準。業務層級 Gherkin（第 5 節）為驗收測試的最高依據。

### 1.2 範圍（MVP）

| 功能領域 | 說明 |
|---------|------|
| 保費即時試算 | 業務員與訪客輸入被保人資料，系統即時回傳保費 |
| 費率表版本管理 | 管理員上傳 CSV 費率表、指定生效日期、版本控管 |
| 試算紀錄查詢 | 業務員查詢自身 90 天內試算歷程；管理員查詢全系統紀錄 |

### 1.3 不在範圍（Phase 2）

- 實際投保申請與送件流程
- 承保核保審查
- 保單管理
- 理賠處理

## 2. 術語表（Glossary）

| 術語 | 定義 | 備註 |
|------|------|------|
| **保費（Premium）** | 要保人依約向保險公司繳納的金額，幣別為新台幣（NTD） | |
| **年繳保費（Annual Premium）** | 每年繳納一次的保費金額（NTD），四捨五入至個位數 | |
| **月繳保費（Monthly Premium）** | 每月繳納一次的保費金額（NTD），含月繳附加費率 3%，四捨五入至個位數 | |
| **繳費總額（Total Payment）** | 整個繳費年期內預計繳納的保費總和（NTD） | 計算方式待釐清，見 OQ-001 |
| **保障倍數說明（Coverage Multiplier Description）** | 說明保額與保費之間的保障倍率關係 | 計算方式待釐清，見 OQ-002 |
| **費率（Rate）** | 每千元保額對應的保費金額，依被保人年齡、性別、繳費年期查詢費率表 | |
| **保額（Sum Assured）** | 被保險人身故或全殘時可獲得的理賠金額，單位為萬元（NTD），須為整數 | |
| **繳費年期（Payment Period）** | 要保人繳納保費的期間，可選 10 年、20 年、30 年、終身繳（以 99 表示） | |
| **足歲（Age in Full Years）** | 以整年計算的年齡；生日當日前以前一年為準 | |
| **費率表（Rate Table）** | 由精算部門提供、依商品代碼區分的費率資料集，每個商品約 500 筆（年齡 × 性別 × 繳費年期） | |
| **費率表版本（Rate Table Version）** | 費率表的一個歷史快照，具有唯一版本識別與生效日期 | |
| **生效版本（Active Version）** | 同一商品在同一時間點唯一有效的費率表版本 | |
| **試算紀錄（Calculation Record）** | 每次試算的完整快照，包含輸入參數、試算結果或失敗原因、業務員識別碼、試算時間 | |
| **業務員（Agent）** | 第一線壽險業務人員，需登入後使用系統 | |
| **系統管理員（Admin）** | 負責費率表維護與全系統紀錄查詢的 IT 維運人員 | |
| **訪客（Guest）** | 未登入的一般使用者，可執行匿名試算，結果不保存 | |
| **商品代碼（Product Code）** | 識別保險商品的唯一代碼 | 格式規範待釐清，見 OQ-003 |
| **匿名試算（Anonymous Calculation）** | 訪客執行的試算，系統不保存任何紀錄 | |

## 3. 使用者故事（User Stories）

### 3.1 保費試算

---

**US-CALC-001**
**身為** 業務員，
**我希望** 輸入被保人年齡、性別、保額、繳費年期與商品代碼後，立即取得年繳保費、月繳保費、繳費總額及保障倍數說明，
**以便** 在客戶面談時即時提供精確報價，提升成交率。

**驗收條件：**
- 輸入五項參數後，系統在 3 秒內回傳試算結果
- 結果包含：年繳保費（NTD）、月繳保費（NTD）、繳費總額（NTD）、保障倍數說明
- 試算紀錄（含輸入參數與結果）自動保存至系統
- 輸入不合法時，系統回傳明確的失敗原因，且失敗紀錄亦保存

---

**US-CALC-002**
**身為** 訪客，
**我希望** 不需登入即可執行保費試算，
**以便** 快速了解保費概況。

**驗收條件：**
- 訪客可輸入相同五項參數並取得試算結果
- 系統**不保存**訪客的試算紀錄
- 訪客無法查詢試算歷程

---

### 3.2 費率表維護

---

**US-RATE-001**
**身為** 系統管理員，
**我希望** 上傳 CSV 格式的費率表並指定生效日期，
**以便** 確保系統使用最新精算費率進行試算。

**驗收條件：**
- 管理員可上傳 CSV 檔案並指定商品代碼與生效日期
- 生效日期不得早於上傳當日
- 上傳成功後，系統建立新版本費率表，狀態為「待生效」
- 生效日期到達後，新版本自動成為該商品的生效版本
- 同一商品同一時間只有一個生效版本

---

**US-RATE-002**
**身為** 系統管理員，
**我希望** 費率表上傳後不可修改，
**以便** 確保費率資料的不可竄改性與稽核追蹤。

**驗收條件：**
- 已上傳的費率表版本不提供修改功能
- 需要更新費率時，只能上傳新版本並指定新的生效日期

---

### 3.3 試算紀錄查詢

---

**US-HIST-001**
**身為** 業務員，
**我希望** 查詢自己最近 90 天內的試算歷程，
**以便** 追蹤與客戶的洽談紀錄及報價歷史。

**驗收條件：**
- 業務員只能查詢自己的試算紀錄，不得查詢他人紀錄
- 查詢範圍限最近 90 天
- 紀錄包含：試算時間、輸入參數、試算結果或失敗原因

---

**US-HIST-002**
**身為** 系統管理員，
**我希望** 查詢全系統所有業務員的試算紀錄，
**以便** 進行業績追蹤與系統使用分析。

**驗收條件：**
- 管理員可查詢所有業務員的試算紀錄
- 查詢結果包含業務員識別碼、試算時間、輸入參數、試算結果或失敗原因

## 4. 業務規則（Business Rules）

### BR-001：被保人年齡限制

| 項目 | 規則 |
|------|------|
| 最低承保年齡 | 0 歲（出生滿 15 天） |
| 最高承保年齡 | 70 歲（足歲） |
| 違反處理 | 試算失敗，失敗原因記錄為「年齡超限」，仍保存試算紀錄（業務員試算時） |

> ⚠️ **OQ-004**：「0 歲（出生滿 15 天）」的判斷邏輯：系統是否需要接受「出生日期」作為輸入，而非僅接受「足歲」？若僅接受足歲，0 歲的 15 天限制如何在業務層面驗證？

---

### BR-002：保額限制

| 項目 | 規則 |
|------|------|
| 最低保額 | NTD 100 萬元 |
| 最高保額 | NTD 5,000 萬元 |
| 保額單位 | 萬元，須為正整數 |
| 違反處理 | 試算失敗，失敗原因記錄為「保額超限」，仍保存試算紀錄（業務員試算時） |

---

### BR-003：繳費年期

| 可選值 | 說明 |
|--------|------|
| 10 | 10 年期 |
| 20 | 20 年期 |
| 30 | 30 年期 |
| 99 | 終身繳 |

> 僅接受上述四個值，其他值視為不合法輸入。

---

### BR-004：費率表版本管理

| 規則編號 | 規則描述 |
|---------|---------|
| BR-004-a | 同一商品在同一時間點只有一個生效版本 |
| BR-004-b | 費率表一旦上傳（版本建立後）不可修改，只能新增新版本 |
| BR-004-c | 新版本的生效日期不得早於上傳當日 |
| BR-004-d | 試算時使用該商品當下最新生效版本的費率 |

---

### BR-005：保費計算精度

| 項目 | 計算公式 | 精度規則 |
|------|---------|---------|
| 年繳保費 | `保額（元）÷ 1,000 × 費率` | 四捨五入至個位數（NTD） |
| 月繳保費 | `年繳保費 × (1/12) × 1.03` | 四捨五入至個位數（NTD） |
| 繳費總額 | 待釐清（見 OQ-001） | 待釐清 |

> **注意：** 保額輸入單位為萬元，計算時須轉換為元（× 10,000）後再代入公式。

---

### BR-006：試算紀錄保存

| 規則編號 | 規則描述 |
|---------|---------|
| BR-006-a | 業務員執行的試算，不論成功或失敗均須保存試算紀錄 |
| BR-006-b | 訪客（Guest）執行的匿名試算，不保存任何紀錄 |
| BR-006-c | 失敗原因分類：`年齡超限`、`保額超限`、`費率資料不存在` |
| BR-006-d | 試算紀錄保存內容：業務員識別碼、試算時間、輸入參數（五項）、試算結果或失敗原因 |

---

### BR-007：試算歷程查詢範圍

| 角色 | 可查詢範圍 |
|------|----------|
| 業務員（Agent） | 僅限自己的試算紀錄，最近 90 天 |
| 系統管理員（Admin） | 全系統所有試算紀錄 |
